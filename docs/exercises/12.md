# Exercise 12: Recover a lost commit with reflog

**Mode:** Local-only practice; not remotely graded.

## Situation

A receipt improvement was committed, but a mistaken reset moved the current branch back. The file change is gone from the current branch, yet the local commit may still be recoverable.

## Start

Run from the launcher:

```text
python3 lab.py start 12
```

Open the workspace path printed by `start`. The workspace starts on `result/ex12` at the baseline after setup created a receipt commit and moved the branch back. That setup occurred inside this workspace, so its local reflog contains the reference movements. No helper tag names the lost commit.

## Inspect this exercise

Inside the workspace:

```text
git log --oneline --graph --decorate HEAD
git reflog --oneline
```

The first command shows the surviving history. The reflog also records earlier local positions, including the lost commit.

## Task

1. Inspect the local reflog and find the commit that introduced the receipt improvement. **Copy its commit ID** and check its contents with `git show COPIED-COMMIT-ID` before using it. Replace the placeholder with the ID you found.
2. Create a branch named `recovery/receipt` pointing to the recovered commit. Switch to that branch.
3. Inspect the recovered receipt and run the local check.

Use the copied commit ID when creating `recovery/receipt`. A name such as `HEAD@{1}` means a position in the **current** reflog; switching branches or moving `HEAD` can change what that position refers to. The copied commit ID continues to identify the same commit. If you use a reflog expression directly in a shell, quote it, for example `git show 'HEAD@{1}'`, and inspect it before moving any ref.

## Success conditions

- `recovery/receipt` preserves the lost commit and is checked out for the check.
- The receipt uses `Borrowed: ` again. Baseline borrowing and search behavior still pass.
- You can explain why the local reflog revealed this committed work and why it is not a backup of every uncommitted edit.

## Check

From the launcher, use the exact workspace path printed at start:

```text
python3 lab.py check 12 --repo "/PATH/TO/YOUR/WORKSPACE"
```

The reflog belongs to this workspace. A fresh clone does not inherit it; restarting creates a new local recovery scenario with its own commit IDs.

## Submission

No remote submission is required. Keep `recovery/receipt` locally while reviewing the recovery process.

## Restart

Run `python3 lab.py start 12` again from the launcher to create a fresh workspace. It leaves the old attempt intact.
