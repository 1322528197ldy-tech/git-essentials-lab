# Exercise 11: Publish rewritten history with a lease

**Mode:** Local-only practice; not remotely graded.

## Situation

A receipt commit has already been published to a simulated shared branch, but its message is still unfinished. Replace it deliberately, using a lease to protect against an unexpected remote update.

## Start

Run from the launcher:

```text
python3 lab.py start 11
```

The workspace starts on `result/ex11` with a receipt commit named `wip receipt`. Setup publishes it to the **local** `practice` remote's `practice` branch. Record the initial remote-tip commit ID printed by `start`; this is the value you expect the remote to have when you publish the replacement. `origin` still refers to your GitHub fork and is not used for this simulation.

## Task

1. Inspect the receipt commit and its published remote value. Amend its message to exactly `feat: improve loan receipt` without losing the `Borrowed: ` code change.
2. Attempt an ordinary push of the rewritten work to the simulated `practice` branch. Observe the non-fast-forward rejection and explain why the amended commit is different.
3. Publish the replacement to the same simulated branch using an **explicit expected-tip lease**. The protected destination ref is `refs/heads/practice`; the expected value is the initial remote-tip ID you recorded, not a newly guessed hash.
4. Confirm that the simulated remote now points to your replacement commit.

The relevant option form is `--force-with-lease=<ref>:<expected>`. Consult the [push reference](https://git-scm.com/docs/git-push) to combine it with the intended remote and source/destination branch mapping.

## Success conditions

- The receipt improvement remains present, and the commit message is `feat: improve loan receipt`.
- The local result and simulated remote branch point to the same replacement commit. The borrowing and search rules remain at baseline values.
- You can explain which remote value the lease protected and why a lease is more specific than an unrestricted force push.

## Check

From the launcher:

```text
python3 lab.py check 11 --repo "/PATH/TO/YOUR/WORKSPACE"
```

## Optional second attempt: observe a stale lease

Create a **fresh** Exercise 11 workspace. Record its initial remote-tip ID, then amend the message again. Before your lease push, run this from the launcher:

```text
python3 lab.py advance 11 --repo "/PATH/TO/YOUR/NEW-WORKSPACE"
```

This adds `docs/teammate-note.md` to the simulated shared branch. Try publishing with the old explicit expected-tip lease. It should reject the update. Fetch and inspect the teammate commit; leave it intact. Do not update the expected ID and force away the teammate's work just to make a push succeed.

The ordinary completion check need not pass for this optional interrupted attempt: its purpose is to observe a rejection and preserve the remote update.

## Submission

No remote submission is required. Both the successful replacement and the stale-lease test use local simulated repositories, not your GitHub fork or another student's work.

## Restart

Run `python3 lab.py start 11` again from the launcher to get a fresh workspace, simulated remote, and expected-tip ID.
