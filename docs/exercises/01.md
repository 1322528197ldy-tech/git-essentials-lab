# Exercise 01: Branch and switch

**Mode:** Submitted result.

## Situation

The catalog currently treats uppercase and lowercase letters as different. You want to improve search in an isolated branch, then integrate the completed change.

## Start

Run from the launcher:

```text
python3 lab.py start 01
```

Open the workspace path printed by `start`. The workspace starts on `result/ex01` at `lab-v1/ex01/start`. The application uses the baseline borrowing rules: two books per member, 14-day loans, and 100 units per overdue day.

## Inspect this exercise

Inside the workspace:

```text
git log --oneline --graph --decorate HEAD result/ex01 lab-v1/ex01/start
```

After creating `feature/search`, include it in the command to compare the feature and result pointers.

## Task

1. Create and switch to a new branch named `feature/search` from the prepared result branch.
2. In `src/library/Catalog.java`, make title search case-insensitive using locale-independent normalization (`Locale.ROOT`). Preserve substring matching and the rest of the catalog behavior.
3. Commit the change on the feature branch. Switch back to `result/ex01` and merge the completed feature into it.

## Success conditions

- Queries with different letter cases find the same matching titles.
- `result/ex01` contains the search change and descends from the original starting point. The borrowing policy remains unchanged.
- The completed work is committed and the working tree is clean.

## Check

From the launcher, use the exact workspace path printed at start:

```text
python3 lab.py check 01 --repo "/PATH/TO/YOUR/WORKSPACE"
```

Inspect the branch graph before and after integration. Explain which branch moved when you committed and which moved when you integrated.

## Submission

Publish `result/ex01` to `origin`. No PR is required for this exercise.

## Restart

Run `python3 lab.py start 01` again from the launcher to create a fresh workspace. It leaves the old attempt intact.
