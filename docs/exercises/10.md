# Exercise 10: Rebase and clean up private commits

**Mode:** Submitted result.

## Situation

Your two private receipt commits are based on the old library policy. A newer upstream history extends the loan period. Replay your work onto that history and present it as one coherent commit.

## Start

Run from the launcher:

```text
python3 lab.py start 10
```

Open the workspace path printed by `start`. The workspace starts on `result/ex10` with two local WIP commits after `lab-v1/ex10/start`: receipt code, then receipt documentation. The prepared upstream history is `lab-v1/ex10/upstream`, which changes loans to 21 days.

## Inspect this exercise

Inside the workspace:


## Task

See the [starting commit graph](../GRAPHS.md#exercise-10-private-work-and-a-newer-base) to locate the newer base and the two private setup commits.

1. Inspect the divergence between your local work and the upstream helper tag.
2. Use interactive rebase to place your receipt work on the prepared upstream history and combine the two private WIP commits into one.
3. Use the exact final commit message `feat: improve loan receipt`, and inspect both the graph and files.

### Interactive rebase editor example

Set your workspace's editor using [Setup](../SETUP.md#5-choose-a-git-editor-before-making-commits) before starting. The todo list orders commits from oldest to newest. For two private commits you intend to combine, its initial shape is:

```text
pick abc1234 wip receipt
pick def5678 wip receipt docs
```

The IDs above are illustrative; **keep the real IDs in your own todo file**. Changing it to the following shape asks Git to edit the first message and fold the second commit into it:

```text
reword abc1234 wip receipt
fixup def5678 wip receipt docs
```

Save and close the todo file. When the commit-message editor opens, enter the required meaningful message, then save and close it too. `fixup` retains the previous commit's message; `squash` also combines the commits but opens an editor to combine their messages. Do not put the final commit message in place of an action word or hash. After the editor closes, inspect `git status`; a conflict may require resolution and `git rebase --continue` before the rebase is complete.

## Success conditions

- `lab-v1/ex10/upstream` is an ancestor of the result. Exactly **one** receipt commit follows it, with no merge commit in that segment.
- The combined commit contains the `Borrowed: ` receipt and `docs/receipt.md`, including its explanation of the borrowed book title.
- Loans last **21 days**. Limits remain two books each, fees remain nonnegative at 100 per day, and search remains case-sensitive.

## Check

From the launcher, use the exact workspace path printed at start:

```text
python3 lab.py check 10 --repo "/PATH/TO/YOUR/WORKSPACE"
```

Compare the new commit IDs with the original local WIP commits. The upstream loan-period change must survive alongside your receipt changes.

Rebase normally preserves each original commit's **author** while creating new commits with new committer information. The combined receipt commit may therefore still show `Lab Setup` as author. That is expected and is not a grading condition. Use `git log -1 --format=fuller` to compare author and committer; rewriting the author is not needed to complete this task.
