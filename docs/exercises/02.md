# Exercise 02: Fork, remotes, and push

**Mode:** Submitted result; remote configuration is local practice.

## Situation

A classmate should be able to run the library demo from your repository. Add a short run guide and publish it to your own fork.

## Start

Run from the launcher:

```text
python3 lab.py start 02
```

Open the workspace path printed by `start`. The workspace starts on `result/ex02` at `lab-v1/ex02/start`. `origin` should point to your fork and `upstream` to the course repository. A local clone, a GitHub fork, and a remote name are different things.

## Inspect this exercise

Inside the workspace:

```text
git log --oneline --graph --decorate HEAD lab-v1/ex02/start
```

Use `git branch -vv` separately to inspect tracking; a history graph does not verify the GitHub page.

## Task

1. Inspect the remote URLs and correct them if needed. Verify that the push destination belongs to your GitHub account.
2. Create `docs/my-run-guide.md`. Include the prerequisites, the exact command `python3 run.py demo`, and a short description of what the demo does. Commit the guide.
3. Publish `result/ex02` to your fork and configure its tracking relationship. Open that branch on GitHub and inspect the committed guide.

## Success conditions

- The committed guide exists on `result/ex02` and includes the runnable demo command.
- The application behavior is unchanged. Your fork displays the result branch and its guide.
- You can explain why pushing did not open a PR and why the `upstream` remote is not the same as a branch tracking relationship.

## Check

From the launcher, use the exact workspace path printed at start:

```text
python3 lab.py check 02 --repo "/PATH/TO/YOUR/WORKSPACE"
```

Use `git remote -v` and `git branch -vv` to inspect local configuration. A local check cannot confirm the contents of a GitHub page; verify the published branch there.

## Submission

Publish `result/ex02` to `origin`. The remote document is reviewable; local remote aliases and tracking configuration are not remotely graded.

## Restart

Run `python3 lab.py start 02` again from the launcher to create a fresh workspace. It leaves the old attempt intact.
